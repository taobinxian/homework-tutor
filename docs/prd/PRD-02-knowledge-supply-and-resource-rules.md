## 1. 需求 / 问题

当前答题与游戏的关系偏直接：答对就打一下、答错就被打。孩子容易感知为“题目换皮”。

知识战场的核心要改成：

> 答题不是攻击动作本身，而是生成战斗资源。孩子做题越好，后面的战斗越爽。

这能减少答题对游戏节奏的打断，也能让孩子形成“学习让我变强”的正反馈。

---

## 2. 目标用户与场景

### 目标用户

- 孩子：希望答题有即时奖励，不因答错马上挫败。
- 家长：希望每局都有真实答题练习。
- 研发：需要明确答题结果如何转成资源。

### 核心场景

1. 关卡开始前，孩子完成 5 道知识补给题。
2. 系统按答题表现发放弹药、技能、护盾。
3. 孩子用这些资源进入战斗。
4. 中途补给点再答 3 道题补充资源。
5. Boss 前完成关键补给，获得破盾道具或大招能量。

---

## 3. 方案概述

一期采用三类补给：

| 补给类型 | 触发时机 | 题数 | 作用 |
|---|---|---:|---|
| 开局补给 | 关卡开始前 | 5 | 决定初始弹药、技能、护盾 |
| 中途补给 | 波次之间 | 3 | 补充资源，修正战斗压力 |
| Boss 补给 | Boss 阶段前/破盾时 | 1-3 | 破盾、大招、关键资源 |

---

## 4. 用户流程

### 4.1 开局补给

```text
关卡详情
→ 点击开始
→ 进入知识补给页
→ 连续答 5 题
→ 展示资源获得动画
→ 进入战斗
```

### 4.2 中途补给

```text
完成第 N 波战斗
→ 出现补给箱 / 能量站
→ 答 3 题
→ 获得资源
→ 继续下一波
```

### 4.3 Boss 补给

```text
Boss 开盾 / 阶段切换
→ 弹出知识破解题
→ 答对破盾或获得大招窗口
→ 答错则 Boss 护盾削弱较少，但不直接失败
```

---

## 5. 核心规则

## 5.1 资源类型

| 资源 key | 名称 | 来源 | 用途 |
|---|---|---|---|
| ammo_basic | 普通弹药 | 答对基础题 | 普通射击 |
| ammo_power | 能量弹 | 连对奖励 | 高伤害射击 |
| skill_freeze | 冰冻技能 | 快速答对 / 连对 | 减速敌人 |
| skill_bomb | 爆裂技能 | 高难题答对 | 范围伤害 |
| shield | 护盾 | 全对 / 连对 | 抵挡伤害 |
| heal_pack | 治疗包 | 复习错题答对 | 恢复生命 |
| pet_energy | 宠物能量 | 连续学习 | 宠物助战 |
| ultimate_energy | 大招能量 | 全对 / Boss 补给 | 释放终极技能 |

## 5.2 基础发放规则

### 开局补给，每题默认：

| 答题结果 | 资源 |
|---|---|
| 答对 | 普通弹药 +6 |
| 答错 | 普通弹药 +2，记录错题 |
| 首次答对且耗时 ≤ 8 秒 | 额外普通弹药 +2 |
| 连对 3 题 | 能量弹 +3 |
| 5 题全对 | 护盾 +1，大招能量 +1 |

### 中途补给，每题默认：

| 答题结果 | 资源 |
|---|---|
| 答对 | 普通弹药 +4 |
| 答错 | 普通弹药 +1，记录错题 |
| 连对 3 题 | 治疗包 +1 或冰冻技能 +1 |

### Boss 补给：

| 答题结果 | Boss 效果 |
|---|---|
| 答对 | Boss 护盾 -50% 或打开弱点窗口 |
| 答错 | Boss 护盾 -20%，记录错题并给提示 |
| 连续答对 Boss 补给题 | 获得大招能量 +1 |

## 5.3 难度修正

按关卡 difficulty 调整奖励，不调整题目正确性规则。

| difficulty | 资源系数 | 说明 |
|---|---:|---|
| 1 | 1.2 | 低年级/入门，更鼓励 |
| 2 | 1.0 | 标准 |
| 3 | 0.9 | 挑战，资源稍紧 |

## 5.4 答错策略

原则：**答错不惩罚到失败，只减少爽感并进入复习链路。**

- 答错仍给少量保底弹药。
- 连错 2 题后，下一题可触发轻提示。
- 连错 3 题后，宠物可请求“排除一个错误选项”。
- 错题必须写入错题库或本轮错题缓冲。

## 5.5 防刷规则

- 同一道题重复答不重复发放资源。
- 退出补给重进时，同一 runId 不重复结算已提交题。
- 已答题结果需绑定 levelRunId。

## 7. API 需求

### 7.1 获取补给题

`POST /api/levels/supply/start`

请求：

```json
{
  "user": "default",
  "levelRunId": "run-001",
  "levelId": "g1-math-upper-001",
  "phase": "opening"
}
```

返回：

```json
{
  "phase": "opening",
  "questions": [],
  "rules": {
    "timeBonusMs": 8000,
    "comboBonus": 3
  }
}
```

### 7.2 提交补给结果

`POST /api/levels/supply/submit`

返回：资源增量、错题列表、下一步动作。

## 8. 验收标准

### 8.1 产品验收

- [ ] 开局补给完成后能看到资源获得反馈。
- [ ] 答对越多，进入战斗的资源越多。
- [ ] 答错不会直接失败。
- [ ] 中途补给能补充资源。
- [ ] Boss 补给能影响 Boss 护盾或弱点窗口。

### 8.2 学习验收

- [ ] 每道补给题记录正确/错误/耗时/知识点。
- [ ] 错题进入错题链路。
- [ ] 补给题来源于当前关卡 topic 或薄弱点 topic。

### 8.3 技术验收

- [ ] 同一 runId 下资源结算幂等。
- [ ] 资源结构可被战斗引擎直接消费。
- [ ] 补给规则可按关卡配置调整。
