# 二级 PRD 04：家长学习报告首发版

- **所属总 PRD**：《学霸奇遇记：知识战场》
- **版本**：v1.0 / 满血首发上线版
- **负责人**：小P
- **目标读者**：polaw、小架、小码、小质
- **说明**：老板要求做完整产品；本文按“可上线发布的满血首发版”定义需求；分阶段只用于工程落地，不降低产品闭环。本 PRD 聚焦“家长能看懂孩子练了什么、哪里薄弱、下一步怎么练”，不扩展完整家长端、账号体系、云同步或付费体系。

---

## 1. 需求 / 问题

知识战场会显著增强游戏体验，但如果家长只能看到关卡数、金币、击败怪物等游戏数据，会担心孩子“只是玩游戏”。

家长报告首发版要解决的问题是：

> 用清晰、可信、可行动的学习数据证明：孩子每次闯关都有学习产出，并告诉家长今天/近 7 日应该关注哪个薄弱点。

报告必须把游戏结果翻译成学习语言：

- 不是“打了几个怪”，而是“练了哪些知识点”。
- 不是“拿了多少金币”，而是“正确率、错题、掌握度有什么变化”。
- 不是“泛泛建议继续加油”，而是“明天优先完成哪个复习副本 / 练哪个知识点”。

---

## 2. 目标与非目标

### 2.1 目标

1. 家长可查看 **今日报告** 与 **近 7 日报告**。
2. 报告展示学习核心数据：学习时长、完成题数、正确率、错题数、知识点覆盖、薄弱点、掌握点。
3. 报告能给出明确建议：推荐复习知识点、推荐复习副本、建议练习量。
4. 报告同时展示少量游戏数据，但游戏数据只作为学习动机解释，不作为主内容。
5. 复用现有本地用户 / 默认用户数据，不引入复杂账号体系。
6. 能为研发提供字段、口径、异常态和验收标准，直接补实现。

### 2.2 非目标

首发版明确不做：

1. 不做完整家长端 App / 独立家长账号。
2. 不做多孩子档案、家庭成员权限、远程绑定。
3. 不做云同步、跨设备报告、微信/短信推送。
4. 不做 AI 长篇评语生成；首发版使用规则模板生成建议。
5. 不做付费订阅、报告导出 PDF、历史月报/学期报告。
6. 不做家长目标配置、学习计划编辑；只展示系统推荐。
7. 不把游戏数据包装成主要价值，报告主轴必须是学习数据。

## 3. 目标用户与场景

### 3.1 目标用户

- **家长**：想确认孩子玩游戏时是否真的在学习，哪里薄弱，接下来怎么复习。
- **孩子**：间接受益；家长能理解并支持孩子继续使用产品。
- **研发 / 测试**：需要明确报告字段、数据口径、空状态和验收方式。

### 3.2 核心场景

1. **当天学习后查看日报**
   - 孩子完成 1-3 个关卡。
   - 家长打开“家长报告”。
   - 查看今天练了哪些知识点、正确率、薄弱点、建议明天练什么。

2. **周末查看近 7 日趋势**
   - 家长查看近 7 日学习时长、题量、正确率趋势。
   - 看到哪些知识点已掌握，哪些连续薄弱。
   - 根据建议安排下周复习重点。

3. **孩子失败/错题较多后查看建议**
   - 孩子某关战斗失败或正确率偏低。
   - 家长报告解释失败背后的学习原因：例如“20 以内退位减法正确率 55%”。
   - 系统推荐复习副本，而不是只提示“继续挑战”。

## 5. 页面 / 模块结构

### 5.1 入口

首发版建议入口放在首页或结算页：

1. **首页入口**：按钮文案「家长报告」。
2. **关卡结算页入口**：按钮文案「查看学习报告」。

入口要求：

- 默认进入“今日”报告。
- 支持切换「今日 / 近 7 日」。
- 不要求登录；使用当前本地默认用户 `default` 或现有用户标识。

### 5.2 页面结构

```text
家长学习报告页
├─ 顶部标题区
│  ├─ 报告标题：今日学习报告 / 近 7 日学习报告

│  └─ 今日 / 近 7 日切换
├─ 学习概览卡
│  ├─ 学习时长
│  ├─ 完成关卡数
│  ├─ 完成题数
│  ├─ 正确率
│  └─ 错题数
├─ 知识点表现模块
│  ├─ 已练知识点
│  ├─ 已掌握知识点
│  └─ 薄弱知识点
├─ 趋势模块（近 7 日展示，今日可隐藏）
│  ├─ 每日学习时长
```

### 5.3 信息优先级

| 优先级 | 模块 | 理由 |
|---|---|---|
| P0 | 学习概览、知识点表现、学习建议 | 直接证明学习产出，满足主 PRD 8.9 / 17 |
| P1 | 近 7 日趋势、推荐复习副本 | 帮助家长判断变化和下一步行动 |
| P2 | 游戏参与模块 | 解释孩子玩了什么，但不能喧宾夺主 |

## 6. 报告字段

## 6.1 今日报告字段

接口建议：`GET /api/reports/daily?user=default&date=YYYY-MM-DD`

### 6.1.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| userId | string | 是 | 当前用户标识，首发版可为 `default` |
| date | string | 是 | 报告日期，格式 `YYYY-MM-DD` |
| hasData | boolean | 是 | 当天是否有学习数据 |
| generatedAt | string | 是 | 报告生成时间 ISO 字符串 |

### 6.1.2 学习概览字段

| 字段 | 类型 | 必填 | 展示文案 | 说明 |
|---|---|---:|---|---|
| learningDurationSec | number | 是 | 学习时长 | 只统计答题/讲解/复习等学习阶段 |
| gameDurationSec | number | 是 | 游戏时长 | 只统计战斗/地图/结算等游戏阶段 |
| totalDurationSec | number | 是 | 总时长 | learningDurationSec + gameDurationSec |
| completedLevels | number | 是 | 完成关卡 | 胜利或失败结算都可计入“参与”，但“完成”只计通关 |
| attemptedLevels | number | 是 | 挑战关卡 | 当天进入并结算的关卡数 |
| completedQuestions | number | 是 | 完成题数 | 有提交答案的题数 |
| correctQuestions | number | 是 | 答对题数 | 首次提交正确计入 |
| wrongQuestions | number | 是 | 错题数 | 首次提交错误计入 |
| accuracy | number | 是 | 正确率 | correctQuestions / completedQuestions |
| reviewedWrongQuestions | number | 否 | 复习错题 | 当天复习错题数量 |

### 6.1.3 知识点字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| practicedTopics | TopicStat[] | 是 | 当天练过的知识点 |
| weakTopics | TopicStat[] | 是 | 当天识别出的薄弱知识点，最多展示 3 个 |
| masteredTopics | TopicStat[] | 是 | 当天达到掌握或保持掌握的知识点，最多展示 3 个 |
| improvedTopics | TopicStat[] | 否 | 正确率或掌握度明显提升的知识点 |

`TopicStat` 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| topicId | string | 是 | 知识点 ID |
| topicName | string | 是 | 知识点名称，如“20 以内退位减法” |
| subject | string | 是 | 学科：math/chinese/english/science |
| grade | number | 是 | 年级 |
| questionCount | number | 是 | 该知识点完成题数 |
| correctCount | number | 是 | 该知识点答对题数 |
| wrongCount | number | 是 | 该知识点答错题数 |
| accuracy | number | 是 | 该知识点正确率 |
| masteryStatus | string | 是 | 未开始 / 学习中 / 薄弱 / 巩固中 / 已掌握 |
| masteryDelta | number | 否 | 掌握度变化，范围 -1 到 1；首发版可选 |
| relatedLevelIds | string[] | 否 | 相关关卡 ID |

### 6.1.4 建议字段

| 字段 | 类型 | 必填 | 说明 |

| 字段 | 类型 | 必填 | 说明 |

### 6.1.5 游戏辅助字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|

## 7. 数据口径

## 7.1 时间口径

| 指标 | 统计口径 |
|---|---|
| 学习时长 | 知识补给答题、Boss 知识题、错题复习、AI 讲解停留时间；不含纯地图浏览和战斗操作 |
| 游戏时长 | 战役地图浏览、战斗阶段、结算动画、奖励展示；不含答题和讲解 |
| 总时长 | 学习时长 + 游戏时长；页面后台/离开超过 30 秒不计入 |
| 日期归属 | 按本地时区自然日 `00:00-23:59`；当前项目默认 Asia/Shanghai |

## 7.2 题目口径

| 指标 | 统计口径 |
|---|---|
| 完成题数 | 用户提交过答案的题目数；跳过/退出未提交不计入 |
| 答对题数 | 首次提交即正确计入答对 |
| 错题数 | 首次提交错误计入错题；同一题多次尝试当日只记 1 次错题 |
| 正确率 | 答对题数 / 完成题数；完成题数为 0 时展示 `--` |
| 有效答题数 | 完成题数；用于主 PRD “每局有效答题数 ≥ 15”验收 |
| 知识点归属 | 优先使用题库题目绑定的 topicId；缺失时归入“未归类知识点”并记录待补数据 |

## 7.3 关卡口径

| 指标 | 统计口径 |
|---|---|
| 挑战关卡 | 进入关卡并产生结算记录 |
| 完成关卡 | 关卡胜利 / 通关计入完成 |
| 失败关卡 | 失败也保留学习数据，但不计入完成关卡 |
| 星级 | 沿用主 PRD 12.1 星级规则 |
| Boss 击败 | Boss 关胜利后计入 |

## 7.4 知识点状态口径

首发版沿用主 PRD 8.8.4 状态：未开始、学习中、薄弱、巩固中、已掌握。

推荐计算规则：

| 状态 | 规则 |
|---|---|
| 未开始 | 无该知识点答题记录 |
| 学习中 | 累计完成 1-4 题，且不满足薄弱/已掌握 |
| 薄弱 | 近 7 日该知识点完成题数 ≥ 3 且正确率 < 70%，或当日错题数 ≥ 2 |
| 巩固中 | 近 7 日完成题数 ≥ 5，正确率 70%-84% |
| 已掌握 | 近 7 日完成题数 ≥ 5 且正确率 ≥ 85%，且最近一次练习正确率 ≥ 80% |

排序规则：

- 薄弱知识点优先级 = 错题数高 > 正确率低 > 最近出现 > 题量高。
- 掌握知识点优先级 = 正确率高 > 题量高 > 最近出现。
- 展示数量：日报薄弱/掌握各最多 3 个；近 7 日各最多 5 个。

## 8. 学习建议生成规则

首发版不接入大模型生成长文案，使用规则模板，保证稳定、可测、可解释。

### 8.1 建议优先级

按以下顺序生成建议，只取最高优先级主建议，可附 1 条次建议：

| 优先级 | 条件 | 建议类型 | 文案方向 |
|---|---|---|---|
| P0 | 存在薄弱知识点 | review_level / topic_practice | 明天优先复习最薄弱知识点 |
| P1 | 今日错题数 ≥ 3 | topic_practice | 建议完成 5-10 道错题复习 |
| P2 | 今日正确率 < 70% | topic_practice | 建议降低难度、先巩固基础题 |
| P3 | 今日学习时长 < 8 分钟或题数 < 8 | continue_campaign | 建议补一小关，保持学习连续性 |
| P4 | 正确率 ≥ 85% 且有掌握知识点 | continue_campaign | 建议继续推进下一关或挑战 Boss |
| P5 | 无数据 | start_learning | 建议今天完成 1 个知识补给关卡 |

### 8.2 模板示例

#### 有薄弱点

```text
今天主要薄弱点是「{topicName}」，共完成 {questionCount} 题，正确率 {accuracy}%。
建议下一次先完成「{reviewLevelTitle}」复习副本，目标练习 {suggestedQuestionCount} 题。
```

#### 表现稳定

```text
今天孩子完成 {completedQuestions} 道题，正确率 {accuracy}%，「{topicName}」表现稳定。
建议继续推进下一关，保持每天 10-15 分钟练习。
```

#### 近 7 日趋势改善

```text
近 7 日孩子在「{topicName}」上的正确率有提升，建议继续用 1-2 次短练习巩固，避免遗忘。
```

#### 无数据

```text
今天还没有学习记录。建议先完成 1 个知识补给关卡，让系统生成第一份学习报告。
```

### 8.3 推荐复习副本规则

1. 若 `weakTopics[0]` 已有关联复习副本，推荐该副本。
2. 若无现成副本，但题库可按 topicId 出题，推荐 `topic_practice`。
3. 若没有薄弱点且今日表现良好，推荐继续当前战役下一关。
4. 推荐题量：
   - 低年级：5 题起。
   - 中高年级：8-10 题。
   - 错题很多时不超过 10 题，避免挫败。

## 9. 空状态 / 异常态

| 场景 | 触发条件 | 展示方案 | 研发要求 |
|---|---|---|---|
| 今日无数据 | 当天 completedQuestions = 0 且无结算记录 | 展示空状态文案 + “去完成一关”按钮 | 不展示 0% 正确率，使用 `--` |
| 近 7 日无数据 | 7 日 totalQuestions = 0 | 展示“近 7 日还没有学习记录” | 趋势图隐藏或置空 |
| 题目无知识点 | 题目缺少 topicId | 归入“未归类知识点” | 记录 warning，便于内容修复 |
| 完成题数太少 | completedQuestions < 3 | 展示“数据较少，仅供参考” | 不强行判断薄弱/掌握 |
| 只有游戏无答题 | gameDuration > 0 且 completedQuestions = 0 | 提醒“本次未产生学习题目” | 检查关卡配置是否绕过补给 |
| 接口失败 | 报告 API 失败 | 展示重试按钮 | 前端不白屏 |
| 日期缺失 | weekly dailyStats 某天无记录 | 补 0 展示 | 保持 7 天连续 |
| 本地存档损坏 | 数据解析失败 | 展示“报告暂不可用” + 重试/返回 | 控制台记录错误，不影响主流程 |

## 10. 首发边界与上线后增强

1. 不做登录注册、家长身份验证、家长 PIN 码。
2. 不做独立家长端导航体系；报告页作为现有产品内页面。
3. 不做消息推送、邮件、短信、微信分享。
4. 不做 PDF / 图片导出。
5. 不做月报、学期报告、排名对比。
6. 不做跨孩子、多设备数据合并。
7. 不做大模型自由生成评语，避免不可控和难测试。
8. 不做复杂图表库；趋势可用简单折线/柱状或列表表达。
9. 不做家长手动布置任务；只展示系统建议和推荐入口。
10. 不做只展示金币、装备、击败数的“游戏战报”。

## 11. 埋点建议

首发版埋点用于验证家长是否能感知学习价值，以及报告是否推动复习。

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| parent_report_open | 打开报告页 | userId, source, reportType |
| parent_report_switch_range | 切换今日/近 7 日 | fromType, toType |
| parent_report_recommendation_view | 建议模块曝光 | recommendationType, topicId |
| parent_report_review_click | 点击推荐复习 | recommendationType, topicId, levelId |
| parent_report_empty_view | 看到空状态 | reportType, reason |
| parent_report_api_error | 报告加载失败 | reportType, errorCode |

关键分析指标：

- 报告页打开率 = 打开报告人数 / 活跃用户数。
- 今日/近 7 日切换率。
- 推荐复习点击率。
- 报告打开后 24 小时内复习副本完成率。
- 家长报告相关反馈：是否能解释“练了什么”。

## 12. 验收标准

### 12.1 产品验收

- [ ] 首页或结算页存在“家长报告”入口。
- [ ] 家长可查看今日报告。
- [ ] 家长可查看近 7 日报告。
- [ ] 报告展示学习时长、完成题数、正确率、错题数。
- [ ] 报告展示具体知识点，而不是只展示关卡/游戏数据。
- [ ] 报告展示薄弱知识点和已掌握知识点。
- [ ] 报告展示下一步学习建议。
- [ ] 今日无学习数据时展示合理空状态，不展示误导性 0% 正确率。
- [ ] 近 7 日报告能展示 7 天连续日期，缺失日期补 0。

### 12.2 学习验收

- [ ] 每道计入报告的题目都有知识点归属；缺失时进入“未归类知识点”并可追踪。
- [ ] 正确率口径为首次提交正确 / 完成题数。
- [ ] 错题数口径与错题库沉淀一致。
- [ ] 薄弱点识别符合本 PRD 第 7.4 节规则。
- [ ] 学习建议优先基于薄弱点/错题，而不是基于游戏失败。
- [ ] 家长报告能解释“今天练了什么”和“下一步怎么练”。

### 12.3 技术验收

- [ ] 实现或补齐 `GET /api/reports/daily?user=default&date=YYYY-MM-DD`。
- [ ] 实现或补齐 `GET /api/reports/weekly?user=default`。
- [ ] 报告数据可由关卡结算、题目答题记录、错题记录、知识点掌握度聚合得到。
- [ ] 不破坏现有题库 picker、错题 API、关卡结算流程。
- [ ] 接口失败时前端不白屏，有重试或返回能力。
- [ ] `npm test` 通过。
- [ ] `npm run validate:bank` 通过。
- [ ] 主流程浏览器手测通过：完成一关 → 产生结算 → 打开今日报告 → 切换近 7 日。

## 14. 后续扩展建议

后续可在 Phase 2/3/4 扩展，但不进入首发版：

1. **完整周报/月报**：增加一周总结、连续学习天数、能力雷达图。
2. **家长目标配置**：家长可设置每天 10 分钟、每周完成某章节等目标。
3. **多孩子档案**：支持多个孩子切换与独立报告。
4. **AI 老师评语**：在规则建议稳定后，再引入可控模板 + AI 润色。
5. **报告分享/导出**：生成图片或 PDF，便于家长留存。
6. **个性化学习路径**：根据近 7 日薄弱点自动调整推荐关卡顺序。
7. **家长认可度反馈**：在报告页增加轻量反馈：“这份报告有帮助吗？”

## 15. 产品结论

家长报告首发版不应做成“游戏战报”，而要做成：

> 一份简洁可信的学习日报 / 近 7 日基础报告，让家长一眼看懂孩子练了什么、哪里薄弱、下一步怎么练。

首发版最关键的交付不是图表复杂度，而是数据口径稳定、知识点可解释、建议可行动。只要这三点成立，家长就能理解知识战场不是纯游戏，而是学习驱动的游戏化产品。
