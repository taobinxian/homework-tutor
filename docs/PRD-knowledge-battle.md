## 1. 背景与问题

### 1.1 当前产品现状

`homework-tutor` 当前已经具备较完整的基础能力：

- 1-6 年级题库，覆盖数学、语文、英语，3 年级起覆盖科学。
- SQLite 题库、课程纲目、生成器、错题库。
- 三种现有关卡引擎：Battle / Shooting / Fighting。
- AI 讲解、拍照出题、TTS 朗读。
- 经验、金币、宝石、宠物、成就、商店、每日任务。

但当前体验仍偏向：

> 做题为主体，游戏作为表现层。

这会导致孩子短期新鲜，但长期吸引力不足。尤其是对低龄儿童而言，如果核心体验仍然是“看到题 → 选答案 → 播动画”，本质上仍像刷题 App。

### 1.2 核心问题

当前最大产品问题不是题库数量，而是：

> 孩子感知不到自己在玩一个真正有趣的游戏，学习和游戏的融合不够深。

具体表现：

1. 游戏操作感弱：主要交互仍是答题点击。
2. 沉浸感弱：题目频繁占据主舞台，打断游戏节奏。
3. 成长目标弱：答题奖励与战斗爽感之间关联不强。
4. 长期留存弱：缺少主线地图、Boss、装备成长、薄弱点副本等长期目标。
5. 家长侧价值表达不足：家长需要明确知道孩子“玩了什么、学了什么、哪里进步了”。

### 1.3 产品判断

本次方向不是继续增加普通题库或换一层游戏皮，而是把产品升级为：

> 一个以射击闯关为核心体验、以知识答题驱动战斗资源、以错题副本提升学习效果的小学生学习游戏。

核心理念：

> 学习不是游戏的中断，而是孩子变强的来源。

## 2. 产品目标

### 2.1 对孩子

让孩子觉得：

> 我不是在刷题，我是在闯关打怪；做对题会让我更强、更酷、更容易通关。

### 2.2 对家长

让家长觉得：

> 孩子确实在玩游戏，但每一局都有明确学习产出，系统还能告诉我薄弱点和复习建议。

### 2.3 对产品

把 `homework-tutor` 从“AI 作业辅导工具”升级为：

> 儿童学习游戏化平台的完整 V1 产品。

---

## 3. 目标用户与使用场景

### 3.1 核心用户

- 小学 1-6 年级学生。
- 低年级重点关注数学、语文、英语基础能力。
- 中高年级逐步增加科学、阅读理解、应用题、综合能力。

### 3.2 决策用户

- 家长。
- 关注孩子是否愿意主动练习、是否真正掌握知识点、是否沉迷纯游戏。

### 3.3 典型场景

1. **放学后 10-20 分钟主动玩一关**
   - 孩子选择喜欢的星球和关卡。
   - 通过答题获得弹药和技能。
   - 完成一场射击闯关。

2. **周末完成一个章节战役**
   - 家长设定学习目标。
   - 孩子完成多个关卡，击败章节 Boss。

3. **考前薄弱点复习**
   - 系统根据错题生成专项副本。
   - 孩子通过打怪修复薄弱知识点。

4. **家长查看日报**
   - 今日完成多少题、正确率、薄弱点、复习建议。

## 4. 产品定位

### 4.1 一句话定位

《学霸奇遇记：知识战场》是一款面向小学生的学习型射击闯关游戏，孩子通过做题获得战斗资源，在高沉浸闯关中通关、养成、复习和成长。

### 4.2 不是什么

- 不是单纯刷题 App。
- 不是题目套动画皮肤。
- 不是拟真暴力 CS。
- 不是开放世界大型 3D 游戏。
- 不是多人竞技游戏。

### 4.3 是什么

- 儿童友好的 2D 科幻射击闯关游戏。
- 学习驱动资源、战斗驱动兴趣、错题驱动复习的闭环产品。
- 能被家长理解学习价值的游戏化学习产品。

---

## 5. 核心设计原则

1. **游戏先成立，学习再融入**
   - 孩子第一感受必须是“好玩”。
   - 学习不能只是外置题卡。

2. **做题让孩子变强，而不是惩罚孩子**
   - 答对获得资源。
   - 答错少拿资源、增加挑战，但不应立即失败。

3. **减少频繁打断**
   - 不做“每开一枪答一道题”。
   - 采用“补给阶段 + 战斗阶段 + Boss 知识机制”。

4. **学习效果可见**
   - 每个关卡必须沉淀正确率、错题、知识点掌握度。
   - 家长能看懂孩子今天练了什么。

5. **儿童友好**
   - 视觉表达偏科幻、泡泡、机器人、怪兽。
   - 避免拟真枪械、血腥、暴力表达。

## 6. 产品总览

完整产品由 6 大系统组成：

1. 主线战役系统
2. 知识补给与战斗资源系统
3. 射击闯关战斗系统
4. 角色 / 武器 / 宠物成长系统
5. 错题与薄弱点副本系统
6. 家长学习报告系统

主循环：

```text
选择战役 / 关卡
→ 知识补给答题
→ 获得弹药 / 技能 / 护盾 / 宠物支援
→ 进入射击战斗
→ 中途补给点 / 精英怪 / 机关
→ Boss 战
→ 结算奖励
→ 错题沉淀 / 掌握度更新
→ 解锁下一关 / 强化装备 / 生成复习建议
```

## 7. 世界观与内容包装

### 7.1 世界观

推荐主题：**星际学园防卫队**。

孩子扮演学园防卫队成员，前往不同知识星球，修复被“混乱怪兽”破坏的知识能量核心。

### 7.2 学科星球

| 学科 | 星球 | 风格 | 示例 |
|---|---|---|---|
| 数学 | 机械星 | 数字机关、能量炮台 | 加减法能量站、乘法工厂 |
| 语文 | 文字森林 | 字词魔法、句子藤蔓 | 拼音花园、成语古树 |
| 英语 | 语言港口 | 单词通讯、外星商店 | 字母码头、对话电台 |
| 科学 | 探索星 | 元素机关、自然怪兽 | 磁力矿洞、空气实验室 |

### 7.3 章节结构示例

```text
一年级数学 · 上册 · 机械星第一章
1-1 数字工厂：0-5 的认识
1-2 加法能量站：5 以内加法
1-3 减法传送门：5 以内减法
1-4 连加连减实验室：连加连减
1-5 Boss：混乱计算兽
```

## 8. 功能需求

## 8.1 主线战役系统

### 8.1.1 功能说明

将当前年级 / 科目 / 学期 / 知识点选择升级为可视化战役地图。

用户不再只选择参数，而是在地图上选择章节和关卡。

### 8.1.2 关卡类型

| 类型 | 说明 |
|---|---|
| 普通关 | 小怪波次 + 基础知识补给 |
| 精英关 | 更强怪物 + 更多知识机制 |
| Boss 关 | 章节 Boss + 知识点综合考察 |
| 复习关 | 由错题和薄弱知识点生成 |
| 挑战关 | 限时、连击、无伤等特殊目标 |

### 8.1.3 关卡状态

- 未解锁
- 已解锁未通关
- 已通关 1 星
- 已通关 2 星
- 已通关 3 星
- 已掌握（该知识点达到掌握标准）

### 8.1.4 验收标准

- 用户能按年级、学科、学期进入对应战役地图。
- 每个知识点至少能映射到 1 个章节节点或关卡组。
- 关卡完成后保存通关状态、星级、正确率、耗时、错题数。
- 已通关关卡可重复挑战。

---

## 8.2 知识补给系统

### 8.2.1 功能说明

知识补给是学习与战斗的核心连接器。

孩子在战斗前或战斗中进入补给答题，答题表现决定战斗资源。

### 8.2.2 补给触发点

1. 关卡开始前：基础补给。
2. 每波战斗后：中途补给。
3. Boss 阶段切换前：关键补给。
4. 复活时：救援补给。

### 8.2.3 补给资源

| 资源 | 获取方式 | 战斗效果 |
|---|---|---|
| 普通弹药 | 答对基础题 | 基础射击 |
| 能量弹 | 连续答对 | 高伤害 |
| 冰冻弹 | 快速答对 | 减速怪物 |
| 爆裂弹 | 高难题答对 | 范围伤害 |
| 护盾 | 连对奖励 | 抵挡伤害 |
| 治疗包 | 复习错题答对 | 恢复生命 |
| 宠物能量 | 连续学习 | 宠物助战 |
| 终极技能 | 全对 / Boss 补给通过 | 大招 |

### 8.2.4 答题表现规则

| 表现 | 奖励 |
|---|---|
| 答对 | 基础资源 |
| 连对 3 题 | 额外技能资源 |
| 全对 | 大招能量 / 稀有掉落 |
| 快速答对 | 暴击加成 |
| 答错 | 少拿资源，记录错题 |
| 多次答错 | 降低战斗补给，但给出提示 |

### 8.2.5 验收标准

- 答题结果必须影响战斗资源。
- 答错题必须进入错题逻辑。
- 补给答题不能导致用户直接失败。
- 每次补给完成后展示资源获得反馈。

---

## 8.3 射击闯关战斗系统

### 8.3.1 功能说明

新增完整的射击战斗阶段，不再只是点击答案靶。

战斗阶段需要具备真实游戏操作：移动、射击、躲避、技能释放、拾取、Boss 机制。

### 8.3.2 推荐形态

优先采用 **2D 横版 / 俯视角儿童射击**。

技术上应适配当前 H5 架构，避免一开始引入 3D 引擎。

### 8.3.3 基础操作

- 左右 / 上下移动。
- 自动瞄准或半自动瞄准。
- 点击 / 长按射击。
- 技能按钮。
- 宠物技能按钮。
- 拾取掉落物。
- 躲避怪物与弹幕。

### 8.3.4 战斗对象

| 对象 | 说明 |
|---|---|
| 小怪 | 基础敌人，数量多，反馈强 |
| 精英怪 | 带护盾、冲锋、召唤等机制 |
| Boss | 多阶段，和知识点机制结合 |
| 机关 | 门、桥、能量塔、传送阵 |
| 补给箱 | 掉落资源或触发答题补给 |

### 8.3.5 战斗模式

1. 清怪推进
2. 限时守护
3. 护送能量核心
4. 生存挑战
5. Boss 对决
6. 薄弱点副本

### 8.3.6 验收标准

- 玩家在战斗阶段至少可以移动、射击、释放技能。
- 战斗资源来自知识补给结果。
- 战斗失败后允许复活或重试。
- 战斗结算能回传：击败数、受伤次数、资源消耗、通关结果。

## 8.4 Boss 知识机制

### 8.4.1 功能说明

Boss 战必须体现知识点，而不是单纯血厚。

### 8.4.2 示例机制

| 学科 | Boss 机制 |
|---|---|
| 数学 | Boss 护盾显示算式，答对/算对才能破盾 |
| 语文 | 错别字怪物混入，需要识别正确词语 |
| 英语 | 听力/单词指令决定 Boss 弱点 |
| 科学 | 根据自然规律选择元素克制技能 |

### 8.4.3 Boss 阶段

- 100%-70%：基础攻击。
- 70%-40%：召唤小怪 / 开启知识护盾。
- 40%-0%：快速攻击 / 关键补给题 / 大招窗口。

### 8.4.4 验收标准

- 每个章节 Boss 至少有 1 个知识点机制。
- Boss 战中至少触发 1 次知识补给或知识机关。
- Boss 通关后展示章节学习总结。

## 8.5 角色系统

### 8.5.1 功能说明

提供儿童友好的角色选择和成长。

角色差异不宜过重，避免低龄用户理解成本过高。

### 8.5.2 初始角色

| 角色 | 风格 | 轻量能力 |
|---|---|---|
| 机械师 | 数字科技 | 弹药上限 +5% |
| 魔法师 | 字词魔法 | 技能冷却 -5% |
| 探险家 | 科学探索 | 掉落拾取范围 +10% |
| 小队长 | 均衡 | 经验 +5% |

### 8.5.3 验收标准

- 用户可选择角色。
- 角色选择影响战斗或成长的轻量数值。
- 不同角色不能造成明显强弱失衡。

## 8.6 武器系统

### 8.6.1 功能说明

武器是孩子长期追求目标之一，同时与学习表现相关。

### 8.6.2 武器类型

| 武器 | 特点 |
|---|---|
| 星能手枪 | 稳定基础武器 |
| 数字冲锋枪 | 连对越多射速越快 |
| 语文魔法杖 | 控制怪物 |
| 英语声波炮 | 范围攻击 |
| 科学元素枪 | 属性克制 |

### 8.6.3 武器成长

- 通关获得经验。
- 正确率影响熟练度。
- 复习错题可获得强化材料。
- 章节 Boss 掉落特殊外观或升级材料。

### 8.6.4 验收标准

- 至少支持武器装备、升级、属性展示。
- 武器成长与学习表现有关。
- 武器不能只依赖金币购买。

## 8.7 宠物系统升级

### 8.7.1 功能说明

保留现有宠物系统，并升级为陪伴 + 战斗 + 学习辅助系统。

### 8.7.2 宠物能力

| 能力 | 说明 |
|---|---|
| 战斗助攻 | 自动攻击或拾取 |
| 答题提示 | 排除错误选项 / 给轻提示 |
| 防护 | 抵挡一次伤害 |
| 鼓励 | 答错后正向反馈 |
| 进化 | 根据学习经验成长 |

### 8.7.3 验收标准

- 宠物能在战斗中可见。
- 宠物至少有 2 类可感知能力：战斗类、学习类。
- 宠物成长与学习行为绑定。

---

## 8.8 错题与薄弱点副本系统

### 8.8.1 功能说明

错题不只是进入错题本，而是自动生成可玩的复习副本。

### 8.8.2 触发规则

当某知识点满足以下任一条件，生成薄弱点副本：

- 近 7 天同一知识点错题 ≥ 3。
- 某知识点正确率 < 70%。
- Boss 关中该知识点连续答错。

### 8.8.3 副本示例

```text
薄弱点警报：退位减法怪兽入侵
副本：退位减法训练营
目标：完成 10 道专项题，击败退位减法 Boss
奖励：退位减法徽章 + 武器强化材料
```

### 8.8.4 掌握度更新

知识点掌握度可按以下状态：

- 未开始
- 学习中
- 薄弱
- 巩固中
- 已掌握

### 8.8.5 验收标准

- 错题能归因到知识点。
- 系统能生成复习副本。
- 复习副本完成后更新掌握度。
- 家长报告中能看到薄弱点变化。

---

## 8.9 家长学习报告系统

### 8.9.1 功能说明

家长侧用于证明产品不是纯游戏。

### 8.9.2 报告内容

- 今日学习时长。
- 完成关卡数。
- 完成题数。
- 正确率。
- 错题数。
- 薄弱知识点。
- 已掌握知识点。
- 推荐明日练习。
- 游戏时间与学习时间比例。

### 8.9.3 报告文案示例

```text
今天孩子学习 18 分钟，完成 3 个关卡，共答题 32 道，正确率 84%。
主要薄弱点：20 以内退位减法。
系统已生成“退位减法训练营”复习副本，建议明天优先完成。
```

### 8.9.4 验收标准

- 家长可查看今日 / 近 7 日学习报告。
- 报告能列出具体知识点和建议。
- 报告不只展示游戏数据，必须展示学习数据。

## 9. 页面与信息架构

### 9.1 页面列表

| 页面 | 说明 |

## 11. API 需求

### 11.1 战役地图

`GET /api/campaign/map?user=default&grade=1&subject=math&semester=upper`

返回：章节、关卡、解锁状态、星级、掌握度。

### 11.2 关卡开始

`POST /api/levels/start`

请求：

```json
{
  "user": "default",
  "levelId": "g1-math-upper-001"
}
```

返回：关卡配置、补给题、初始资源。

### 11.3 补给提交

`POST /api/levels/supply/submit`

提交答题结果，返回战斗资源。

### 11.4 关卡结算

`POST /api/levels/finish`

提交：

- 战斗结果
- 答题结果
- 错题
- 耗时
- 击败数
- 资源消耗

返回：

- 星级
- 奖励
- 掌握度变化
- 是否生成薄弱点副本

### 11.5 家长报告

`GET /api/reports/daily?user=default&date=YYYY-MM-DD`

`GET /api/reports/weekly?user=default`

## 12. 数值规则初稿

### 12.1 星级规则

| 条件 | 星级 |
|---|---|
| 未通关 | 0 星 |
| 通关且正确率 < 80% | 1 星 |
| 通关且正确率 ≥ 80% | 2 星 |
| 通关且正确率 = 100% 或达成特殊目标 | 3 星 |

### 12.2 奖励规则

基础奖励：

```text
经验 = 星级 × 10 + 答对题数 × 2
金币 = 星级 × 4 + 答对题数
宝石 = 3星关卡小概率或章节 Boss 奖励
```

### 12.3 战斗资源规则

- 每答对 1 题：普通弹药 +5。
- 连对 3 题：技能能量 +1。
- 全对补给：额外护盾 +1。
- 答错：记录错题，不给对应资源。
- 错题复习答对：治疗包或强化材料。

## 14. 优先级与开发分期

老板要求做完整产品；实际开发仍需要分阶段交付完整能力。这里的分期是工程组织方式，不是降低产品完整度。

### 14.1 Phase 1：完整 V1 核心闭环

必须包含：

1. 战役地图。
2. 关卡配置。
3. 知识补给答题。
4. 真正射击战斗阶段。
5. Boss 战基础机制。
6. 战斗结算。
7. 错题沉淀。
8. 家长日报。
9. 角色 / 武器 / 宠物基础接入。

验收目标：孩子能完整体验“选地图 → 做题补给 → 射击战斗 → Boss → 结算 → 复习建议”。

### 14.2 Phase 2：成长与复习强化

包含：

1. 武器升级。
2. 宠物技能。
3. 薄弱点副本自动生成。
4. 知识点掌握度。
5. 周报。
6. 更多关卡类型。

### 14.3 Phase 3：内容扩展与运营

包含：

1. 更多星球主题。
2. 每周挑战。
3. 节日活动。
4. 更多 Boss。
5. 更多装备和外观。
6. 关卡配置工具化。

### 14.4 Phase 4：个性化学习

包含：

1. 自适应难度。
2. 个性化出题。
3. AI 老师角色。
4. 家长目标配置。
5. 多孩子档案。

## 15. 不做范围

当前阶段明确不做：

1. 拟真 3D 真人 CS。
2. 多人在线 PVP。
3. 开放世界。
4. 复杂社交。
5. 氪金式商城。
6. 暴力血腥表现。
7. 强竞争排行榜。
8. 大型账号体系，除非后续家长端需要。

理由：

- 成本高。
- 不适合低龄儿童。
- 容易让游戏目标吞掉学习目标。
- 当前 H5 技术栈更适合高完成度 2D 产品。

## 16. 风险与应对

### 16.1 游戏过强，学习被弱化

风险：孩子只想战斗，不想答题。

应对：

- 战斗资源强绑定答题表现。
- 关键 Boss 机制必须依赖知识点。
- 家长报告明确学习产出。

### 16.2 学习打断游戏节奏

风险：频繁弹题降低沉浸感。

应对：

- 使用补给阶段，而不是每次攻击都答题。
- 单次补给集中 3-5 题。
- 战斗阶段保持 30-90 秒连续体验。

### 16.3 开发复杂度上升

风险：完整产品涉及战斗、成长、报告、数据多系统。

应对：

- 先定义稳定接口：关卡配置、资源、结算、掌握度。
- 前端战斗引擎与题库 API 解耦。
- 每期保证端到端完整闭环。

### 16.4 儿童挫败感

风险：题目或战斗过难导致放弃。

应对：

- 答错不直接失败。
- 提供宠物提示、护盾、复活补给。
- 难度自适应逐步引入。

## 20. 产品结论

本产品不应继续停留在“答题 + 动画反馈”的层面。

下一阶段要把核心体验升级为：

> 孩子通过学习获得力量，在真正好玩的射击闯关中使用这些力量，并通过错题副本持续变强。

这是 `homework-tutor` 从工具型产品升级为完整儿童学习游戏产品的关键一步。
