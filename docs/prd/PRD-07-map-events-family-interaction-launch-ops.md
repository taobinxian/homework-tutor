# PRD 07：地图事件、家庭互动与上线运营验收

- **所属总 PRD**：《学霸奇遇记：知识战场》
- **版本**：v1.0 / 满血首发上线版
- **负责人**：小P
- **目标读者**：研发、测试、产品、发布负责人

---

## 1. 需求 / 问题

满血版不能只有线性关卡。孩子需要探索惊喜，家长需要轻量参与，团队需要上线可观测和风险边界。

本 PRD 覆盖：

1. 地图事件 / 宝箱 / 分支挑战。
2. 家长报告反哺任务。
3. 家庭互动：亲子表扬卡、家长 Boss 出题。
4. 上线验收清单、埋点、可观测性、风险边界。

---

## 2. 地图事件 / 宝箱 / 分支挑战

### 2.1 首发必须做

| 类型 | 触发 | 玩法 | 奖励 |
|---|---|---|---|
| 地图宝箱 | 通关后或地图节点 | 答 1-3 题开箱 | 金币、材料、徽章碎片 |
| NPC 提示 | 进入薄弱知识点章节 | 给学习提示或推荐悬赏 | 无或少量鼓励奖励 |
| 分支挑战 | 主线节点旁 | 限时/连对/错题复仇 | 稀有装备、宠物经验 |

### 2.2 规则

- 宝箱题必须来自当前或最近知识点，避免纯抽奖。
- 分支挑战不阻塞主线，但可提供更好奖励。
- 地图事件每天数量有限，避免孩子只刷事件不学主线。

首发限制：
- 每日宝箱最多 3 个。
- 每章至少 1 个分支挑战。
- NPC 提示只用规则模板，不接入不可控长文本生成。

### 2.3 数据字段

`map_events`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 事件 ID |
| user | string | 用户 |
| level_id | string | 关联关卡 |
| event_type | string | chest / npc / branch |
| config_json | text | 题数、奖励、知识点 |
| status | string | available / completed / expired |
| created_at / completed_at | datetime | 时间 |

## 3. 家长报告反哺任务

报告不能只是“看数据”，必须能生成下一步行动。

### 3.1 报告建议类型

| 类型 | 触发 | 行动 |
|---|---|---|
| weak_review | 存在薄弱点 | 生成薄弱点悬赏 |
| praise | 今日有进步或通关 | 生成表扬卡 |
| boss_question | 家长想参与 | 创建家长 Boss 题 |
| continue_campaign | 正确率高且无明显薄弱 | 推荐下一主线关 |

### 3.2 操作入口

在家长报告建议模块提供：
- 「生成复习悬赏」
- 「发一张表扬卡」
- 「出一道 Boss 题」
- 「继续下一关」

### 3.3 验收

- [ ] 报告识别第一薄弱点并生成悬赏。
- [ ] 表扬卡创建后孩子侧首页/结算页可见。
- [ ] 家长 Boss 题创建后能进入孩子挑战列表。
- [ ] 所有任务均本地保存，刷新不丢失。

## 4. 家庭互动

### 4.1 亲子表扬卡

目标：让家长用低成本正反馈强化孩子学习动机。

卡片来源：
- 家长报告手动生成。
- 系统在达成高光后推荐家长确认。

卡片模板：
- “今天你掌握了 {topic}，太棒了！”
- “你成功净化了 {monsterName}，继续保持！”
- “你完成了 {bountyName}，这是认真复习的结果。”

孩子侧展示：
- 首页弹窗或信箱。
- 可领取少量非付费奖励：金币、基地装饰材料。

限制：
- 表扬卡不做外发、不分享社交平台。
- 不使用羞辱或比较文案。

### 4.2 家长 Boss 出题

目标：家长轻量参与，不做复杂 UGC 平台。

首发形式：
- 家长输入题干、选项、正确答案、知识点。
- 或从错题/薄弱点中选择一题改成 Boss 题。
- 保存为本地 `parent_boss_questions`。

孩子挑战：
- 地图出现“家长 Boss 挑战”。
- 答对破盾并获得表扬卡/徽章。
- 答错进入错题怪兽链路，但文案弱化惩罚。

风险边界：
- 不上传、不公开、不分享。
- 家长题默认需要本机输入，不做开放社区题库。
- 输入内容只做本地展示；若后续支持 AI 审核再扩展。

## 5. 上线埋点与可观测性

### 5.1 全链路关键事件

| 模块 | 事件 |
|---|---|
| 地图 | campaign_open, level_node_click, map_event_view, branch_challenge_start |
| 战斗 | level_start, supply_answer_submit, combo_reach, boss_shield_break, level_finish |
| 错题 | wrong_question_record, wrong_monster_created, bounty_generated, bounty_complete |
| 成长 | mastery_level_up, reward_item_gain, badge_unlock, knowledge_base_open |
| 报告 | parent_report_open, parent_report_review_click, parent_report_task_create |
| 家庭 | praise_card_create, praise_card_claim, parent_boss_create, parent_boss_finish |
| 错误 | api_error, storage_error, question_load_error, report_generate_error |

### 5.2 本地优先实现

首发可先将埋点写入本地表/日志文件，支持导出调试：

`analytics_events(id, user, event_name, payload_json, created_at)`

要求：
- 不记录敏感隐私。
- 题干可记录 hash 或 question_id，默认不记录完整家长自定义内容。
- 错误日志包含 errorCode、接口、时间、简短 message。

## 6. 上线验收清单

### 6.1 功能闭环

- [ ] 主线地图、关卡、Boss 可完整跑通。
- [ ] 宝箱、NPC、分支挑战至少各有一个真实事件。
- [ ] 错题怪兽、薄弱点悬赏、掌握度成长形成闭环。
- [ ] 宠物/装备/徽章/知识基地均可获得和查看。
- [ ] 家长报告能反哺悬赏任务。
- [ ] 表扬卡和家长 Boss 出题能本地闭环。

### 6.2 数据一致性

- [ ] 一次答题只记一次结果，重复提交不重复加奖励。
- [ ] 错题、掌握度、报告、图鉴数据口径一致。
- [ ] 奖励结算失败时可重试或不丢失。
- [ ] 本地数据库迁移不破坏已有数据。

### 6.3 体验与安全

- [ ] 儿童失败文案友好，不羞辱、不比较。
- [ ] 无付费诱导、无陌生人社交、无外链社区。
- [ ] 家长自定义内容只在本地使用。
- [ ] 家长报告主轴是学习数据，不被游戏奖励喧宾夺主。

### 6.4 技术可观测

- [ ] 关键事件能在本地 analytics 表查到。
- [ ] 关键接口失败有 errorCode 和日志。
- [ ] 可用脚本生成测试学习数据并回归报告。
- [ ] 首屏和战斗页加载失败有降级提示。

---

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 功能过多导致首发拖期 | 按 Phase A-C 落地，但首发必须闭环，不做静态占位 |
| 游戏奖励掩盖学习价值 | 家长报告坚持真实学习数据，装备加成不污染掌握度 |
| 答错怪兽造成挫败 | 文案定位为“发现挑战”，净化而非惩罚 |
| 家长 Boss 出题内容不可控 | 本地优先，不外发；上线后再考虑审核 |
| 埋点涉及隐私 | 默认记录行为和 ID，不记录完整私密内容 |
